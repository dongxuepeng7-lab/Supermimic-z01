# 三机九小时诊断实验：2026-11-23

本轮用于定位“世界模型预测改善为什么没有稳定带来策略收益”。它是新开发协议，不是继续运行旧的八小时队列，也不是论文的正式优越性检验。完整七组目标保留，当前只训练 A+/B；C、C-perm、D 仍等待响应数据有效性和方法条件满足。计划与冻结文件：`configs/ral/diagnose_nine_hour_v1.json`、`release/ral/diagnose_nine_hour_protocol_v1.json`。

## 1. 现有结果到底说明了什么

依据 `release/ral/online_night01_review_20261123.json` 和 `SCI论文草稿/RA-L_Actuator_World_Model/final_20261123/` 中的论文：

- **训练已经包括策略、价值网络和世界模型。** 4090 完成 20 对、5080 完成 11 对 A+/B，共 62 个模型；每模型 5,000 次策略更新、25,000 次世界模型更新、12,865,536 个环境转移。当前数据不是“全部为零”：4090 的 A+/B 平均完成率为 89.11%/89.85%，5080 为 88.90%/87.79%。
- **结构带来的收益不稳定。** 两批 B−A+ 分别为 +0.74 和 −1.12 个百分点；GPU、种子批次不同，不能据此断言显卡导致差异。最后 s84、s46 的 B 明显退化，两队列按旧规则停止。全部负例必须保留。旧队列按结果提前停止，当前均值只能描述这些已完成样本。
- **前向拟合与响应/控制存在脱节。** B 的校准集 32 步角度 RMSE 平均相对改善约 3.09%/5.30%，但响应误差相对 A+ 略差，且仅比零响应基线好约 0.20%/0.21%。这不足以支持“动作导数已准确”的主张。
- **响应标签与训练后端的一致性尚未成立。** 3090 全部 400 fit + 116 cal 块的两次检查分别失败 65/516、67/516，跨进程重复性失败 15/516。CPU 原始标签重放和 CPU 场景间比较通过；差异集中在 CPU/GPU、GPU 重复响应。失败类别重叠，不能将计数相加。该结果不能直接推出文件损坏，也不能直接证明某一个数值选项就是原因。
- 早期冻结模型策略的零完成率是真实记录；后来的在线恢复同时改变了训练数据、归一化及目标，不能将恢复全部归功于其中一个因素。新 5,000 次更新模型的权重目前没有回传到本机，元数据已审计，实际权重将在原训练机优先核验。

## 2. 理论上应检查的两个环节

策略优化依赖模型对动作的导数及其沿时间的乘积，而轨迹 RMSE 只约束预测值。因而低 RMSE 不保证低梯度误差，也不保证更高的动作完成率。论文中的误差界是有条件关系，不能代替实测成功率。

当前世界模型拟合窗口为 **8 步（0.16 s）**，策略反传窗口为 **32 步（0.64 s）**。长时域可能放大未被拟合目标充分约束的误差，但“8 对 32”本身不是已证实的代码错误。需要分别检验缩短策略时域和延长拟合时域。

B 的显式输入包含 PD 力矩限幅，以及 `friction × tanh(qd/0.01)`。限幅区间外动作导数为零；摩擦近零速度处斜率为 `friction/0.01`，可能造成敏感性问题。当前输入是控制步起点的瞬时近似，物理仿真则每 20 ms 内执行四个 5 ms 子步，且 MuJoCo 的摩擦约束不等于该平滑公式。这些都是待验证机制，不直接改掉公式后宣称修复。

新诊断保存逐块自动微分方向导数、模型中心差分、CPU 物理中心差分、夹角余弦、限幅比例、摩擦局部斜率，并覆盖 1/2/4/8/16/32 步。它衡量开环关节响应，**不等于完整的 actor/critic/reward 策略梯度**。CPU 参考本身也不能替代训练 GPU 响应验证。

中心差分除以 `2ε`，会放大数值误差；接触切换和有限扰动的非线性也会造成与局部导数不一致，所以不同幅度要一起检查，不能看到差值就认定自动微分错误。A+ 的限幅统计按相同 PD 代理离线计算，A+ 模型本身仍输入原始动作，不能将这项统计解释为 A+ 也采用了 B 的限幅通道。

MuJoCo 官方说明 Warp 与 CPU 在精度及 GPU 运算次序上可能有差异，约束求解会影响可重复性。因此先用冻结依赖定位问题，而不是直接升级库或放宽阈值。参考：[MuJoCo Warp 官方说明](https://mujoco.readthedocs.io/en/latest/mjwarp/index.html)。本机冻结环境为 MuJoCo/MuJoCo Warp 3.11.0、Warp 1.16.0、mjlab 1.6.0；运行包继续使用现有 `uv.lock`。

## 3. 三台电脑分别做什么

**5080：策略时域对照。** 每个新种子训练四个模型：A+/B × 策略时域 32/8；世界模型窗口保持 8。从种子 301 开始，每次加 4。若短时域改善 B 的控制，同时梯度诊断显示长时域偏差扩大，支持“长时域误差传播是问题之一”；若 A+、B 同样改善，优先解释为共同的时域效应，不能当作 B 独有优势。

**4090：世界模型拟合时域对照。** 每个新种子训练四个模型：A+/B × 模型窗口 8/32；策略时域保持 32。从种子 303 开始，每次加 4。若长窗口减少 32 步误差且改善策略，支持拟合覆盖不足的解释；若只改善预测而不改善控制，应继续检查动作响应/导数而非追加相同预测训练。

两台训练机先在最多 45 分钟内检查旧轮“第一对 + 触发停止的一对”：5080 的 s6/s46，4090 的 s8/s84。对真实归档校验审计哈希、实际初始化、最终权重和训练预算，重新评估并保存终止轨迹与梯度诊断。旧模型缺失则明确记录跳过，新的四模型对照不等待传输。可用 `--prior-session` 指定旧结果目录。

**3090：响应后端定位，不训练新策略。** 不需要等待新模型传输。

1. 对全部 516 个 fit/cal 块，比较图捕获批处理、即时执行批处理、即时执行单世界三种模式；每种模式独立启动两个进程，检查原方向、0.5/1/2 倍扰动、4/8 步。
2. 剩余时间检查预先确定的新扰动方向（种子 1001–1256），覆盖 1/2/4/8/16/32 步。每个 split 从旧审计失败块、通过块各固定取 12 个，共 48 块；每个方向同样完成三模式 × 两进程。新方向按完整 32×26 目标角序列归一化，所有模式使用相同输入，短时域不重新归一化。
3. 保留原始轨迹、求解器迭代数、约束数量、缓冲溢出、初始 warm-start 转移和图捕获状态变化。每次新方向仍单独重放原始方向以验证原标签。保留原阈值和全部负结果，未读锁定 test 数组。

3090 的 48 块是故障富集诊断样本，不能将其失败率当作全库失败率。一个新方向也不是一个策略训练种子。若图捕获与即时模式不同，下一轮针对图执行检查；若批处理与单世界不同，检查并行场景/求解器；若三者都失败，继续针对精度、接触约束及有限差分信噪比验证。通过这轮也不会自动启动 C。

## 4. 九小时预算与判断方式

- 从启动起总计 9 小时，包含校验、编译、训练、评估、诊断和归档，预留最后 120 秒收尾。单子任务最长 90 分钟。大任务到截止时间中断，保留已有产物，未完成四模型块不纳入主对照。
- 训练预算按更新数和环境步数匹配：每模型仍为 5,000/25,000/12,865,536。H=8 和 H=32 的策略展开计算量不同，WM=32 与 WM=8 的监督展开计算量不同，**不得据此宣称等算力效率优势**。
- 每模型按固定 EMA 最终权重在 identified 训练参考条件下评估两次，每次全部 163 动作；第 0 次为主结果，第 1 次只检查重复性。不是未见动作、未见物理条件或实机验证。
- 每个四模型块实际核对初始 actor/critic 张量一致。时域顺序和组顺序预先交替；不按当轮结果调参、挑种子、择优挑评估重复。
- 主描述量是同一机器内 `(B−A+)干预 − (B−A+)基线`，同时报告 A+、B 各自变化与所有负例。两台机器的不同因素不合并作显卡因果比较。
- 旧控制保留阈值照常计算，但新诊断协议不因一次有限负收益停止整个队列；它继续完成预定块，收集原因证据。NaN、无效数据、子进程错误、空间不足或截止时间则停止。这并未把旧失败改写成通过。
- 旧轮训练时间约为每模型 4090 5.66 分钟、5080 6.91 分钟；新轮增加了四模型对照、终止轨迹及梯度诊断，WM=32 也更慢。因此不能用旧的每模型时间承诺本轮固定数量。安排目标约 5080 8–12 个、4090 6–10 个完整种子块，**仅是排程估计**；实际数量以判断文件为准。队列预排 64 块，不足以继续时不空转凑时间。
- 输出上限 16 GiB，分区至少保留 15 GiB，开始新工作还要求 2 GiB 临时余量；即建议启动前有至少 33 GiB 可用空间。触及限额会提前停止，不承诺无条件跑满九小时。新模型归档逐字节验证后才清理本队列冗余优化器文件；旧归档保留。

## 5. 同步与启动

将 `release/ral/ral_diagnose_9h_code_20261123.tar.gz` 及同名 `.sha256` 复制到各机 Downloads。此包覆盖项目代码/配置和必要协议，不包含数据、旧模型或虚拟环境；先保存你在其他机器上的本地代码改动，再在**已有项目根目录**执行：

```bash
(cd ~/Downloads && sha256sum -c ral_diagnose_9h_code_20261123.tar.gz.sha256)
tar -xzf ~/Downloads/ral_diagnose_9h_code_20261123.tar.gz -C .
uv sync --locked
mkdir -p logs/ral_9h
```

三台机器均须已有真实 `data/motions/z01_lafan_v2_clean/*.npz`、原 `data/ral_pairs_v1/manifest.json` 及 fit/cal 文件、模型资产。无需重新生成响应数据；不要解压早期含失效链接的 ZIP。冻结校验会拒绝不一致的数据/源码。原旧模型默认位于 `logs/ral_online_8h/online_night01_机器号/models/`。

分别在对应机器执行以下一条；**不要把三个命令放在同一台电脑上运行**：

```bash
# 5080
nohup bash scripts/ral_5080_diagnose_9h.sh --out logs/ral_9h/diag01_5080 > logs/ral_9h/diag01_5080_console.log 2>&1 &
```

```bash
# 4090
nohup bash scripts/ral_4090_diagnose_9h.sh --out logs/ral_9h/diag01_4090 > logs/ral_9h/diag01_4090_console.log 2>&1 &
```

```bash
# 3090
nohup bash scripts/ral_3090_diagnose_9h.sh --out logs/ral_9h/diag01_3090 > logs/ral_9h/diag01_3090_console.log 2>&1 &
```

GPU 型号不符、同一可见 GPU 有其他队列或预检查失败，会留下可读状态与原因。已存在的输出目录拒绝覆盖；修复问题后使用 `diag02_...` 新名称，不对半途模型自动续训。控制台出现 `nohup: ignoring input` 是正常提示，以后续状态为准。

例如 5080 查看进度与判断（其他机器替换编号）：

```bash
tail -n 50 logs/ral_9h/diag01_5080_console.log
bash scripts/ral_diagnose_9h_judge.sh --out logs/ral_9h/diag01_5080
```

运行中判断只汇总完整块；不会将当前模型算作完成。结束时自动产生 `status.json`、`judgment.json` 和 `logs/ral_9h/diag01_机器号_review.tar.gz`。先回传三份 **review.tar.gz + console.log**。审阅包包含诊断数字和终止原因，不含权重及大数组；模型留在各块的 `models/`，3090 原始轨迹留在 `backend/`，随后按需要选择传输，禁止只保留表现好的模型。

## 6. 这轮结束后如何决定

先看是否存在足够完整、同初始化、同预算的四模型块，再检查主完成率差值、重复波动、终止原因和梯度指标是否相互支持。不要仅凭一个正值或一个通过标记认定假设成立。如果时域调整未带来一致收益，应该缩小或修改论文的贡献主张，继续针对显式力矩近似进行单因素检验；不能用理论值填补失败的实验。

本轮已经实现的“解决”是把诊断变量、配对条件、时限和结果完整性固定下来。真正修复训练机制仍取决于九小时实验的结果。响应后端、固定样本多种子验证和独立测试条件没有补齐前，不升级成正式 RA-L 结论。

## 7. 本地实现验证

2026-11-23 已通过 34 项相关自动检查、三个机器入口预演和错误 GPU 留存状态检查。在本机 RTX3090 上实跑六个小网络（A+/B × 三种配置，每个 6 次更新），实际 actor/critic 初始张量一致；三种后端模式各完成 2 块、32 步新方向检查，输入与 CPU 参考跨模式一致。另用正式网络宽度、批大小和 1,024 环境执行 B/WM32 的 2 次更新，完整训练与归档检查通过。后端小样本仍有物理门槛失败，不能当作修复证据。详见 `release/ral/diagnose_nine_hour_validation_20261123.json`。九小时队列尚未启动；小测试结果不进入论文统计。
