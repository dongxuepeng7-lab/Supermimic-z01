# Z01 v1.6 模型与动作处理说明

日常安装、数据构建、训练和播放见[项目 README](../README.md)。原始模型结构与惯性来源见 [Z01 模型说明](../Z01_v1.6_whole_body/README.md)。本文记录训练接入、标定和筛选的具体约束。

## 模型与控制

- 原始模型：`Z01_v1.6_whole_body/`；26 个转动关节，包括 2 个头部关节。
- 训练模型：`assets/z01/robot.xml`，由 `tools/data/z01_data.py prepare` 生成。
- 控制参数：`assets/z01/control.json`，包含 PD 增益、armature、被动阻尼/摩擦、默认站姿及碰撞排除项。

训练 MJCF 保留原始质量、惯性、关节轴、角度和力矩上限；移除原模型地面，交由 mjlab 场景提供；将 motor 改为 PD 位置驱动并启用自碰撞。源模型的近似碰撞盒在腰颈处重叠，因此排除两对碰撞：`base_link` / `waist_pitch_link`、`waist_pitch_link` / `head_pitch_link`。

腿部默认站姿通过根部高度 0.97 m、足底水平的 IK 得到。5 ms 步长下的 5 秒 CPU 无支撑站立检查只验证当前仿真初始化。骨盆沿用的近似惯量、上半身安装偏移，以及全部控制参数，仍需要 CAD 或硬件数据校准。修改控制参数后重新生成资产，并为实验保存对应配置；已有权重依赖训练时的控制参数。

镜像符号由实际关节轴推导。`joint` 参考接口和 `sparse5` 头部/腕部/踝部映射均已接入。

## G1 → Z01 标定与数据来源

重定向使用 human-humanoid-tools 的 `ed8b350` 提交及 `all` 依赖，`mimic` 配置、Newton 后端、24 次 IK 迭代、50 Hz 输出。预设写入 `data/hhtools_robots/`，无需修改外部工具仓库。

v2 标定将 Z01 的肩到肘、肘到腕方向对齐到 G1 零姿态骨架：G1 零姿态前臂朝前，Z01 全零姿态前臂朝下。通过有界几何拟合得到左右镜像的肩 pitch/roll 和肘 yaw/pitch，肘 pitch 约为 -82/+82 度。文件为 `assets/hhtools_robots/z01/r2r_calibration_g1.yaml`；生成资产时保留该文件，不回退为零标定。

这属于资产对齐，不是实机标定。Z01 单臂 5 自由度，无法复现 G1 单臂全部 7 自由度姿态。G1 几何、源动作与 CSV 交换脚本只服务于此重定向和对照流程。

`data/raw/z01_v2/retarget_manifest.json` 记录资产、标定、源 NPZ 的哈希，以及 HHT 提交、并行数和参数。构建器检查这些输入，避免复用不同实验的 CSV。历史清单中已移除的 RP1 预设条目不参与 Z01 输入比较。

## 轨迹约束

IK 结果先保存到 `z01_lafan_v2_ik`，再由 `tools/data/condition_z01.py` 处理：

1. 使用 OSQP 对整段超限关节拟合，满足 URDF 角度范围与声明速度的 90%；避免因果裁剪积累相位延迟。
2. 保留 50 Hz、帧数、根部 xy、根部朝向和时间线。训练加载器对已有 50 Hz 样本直接加载，不再插值。
3. 基于碰撞盒和可见足部网格，平滑地向上修正根部高度，使足底至少离地 1 mm；根部修正的竖直速度上限为 0.5 m/s。
4. 在实际导出的 float32 数据上重新验证所有约束。

只重跑约束与筛选：

```bash
uv run python tools/data/condition_z01.py \
  data/motions/z01_lafan_v2_ik data/motions/z01_lafan_v2 \
  --clean-out data/motions/z01_lafan_v2_clean
```

## 逐帧筛选

筛选阈值是当前数据处理策略，不是硬件规格。任意帧满足以下任一条件时剔除对应区间：

- 身体穿地或自碰撞穿透超过 3 cm。
- 关节角度修正超过 20 度。
- 根部抬升超过 10 cm。
- 源前臂朝前而目标前臂朝后：在各自躯干坐标系下，归一化肘到腕向量同时满足 G1 x > 0.25、Z01 x < -0.25。

整段逐帧通过时保留原动作；否则剔除坏帧及前后各 0.5 秒，保留至少 10 秒的连续区间，名称包含 `__segNNN`。`selection.json` 记录源动作、准确帧范围与排除原因。源/目标帧数必须对应；截断检查中无法进行手臂对照时，报告会显式记录该项未检查。完整修正动作仍保留供复查。

已有 v2 报告（`logs/z01_v2_audit/selected_summary.json`）记录：163 段、233,935 帧、约 1.299 小时；选中区间没有前后臂方向标记，最大关节速度约为 URDF 上限的 0.899912 倍，最小碰撞/可见足底间隙约 1.001 mm。`dance1_subject1`、`fallAndGetUp1_subject1`、`fallAndGetUp3_subject1` 没有可用的 10 秒区间。完整修正库仍有 3 个动作合计 20 帧的手臂方向标记，相关区间已从训练集排除。这些是既有报告结果，不代表后续每次构建的结果。

`tools/audit_z01_motions.py` 逐帧对比 G1 源与 Z01，输出 `report.json`、`clips.csv` 和诊断 NPZ；不会重新生成动作。早期 `z01_lafan_clean` 只做过每段最多 100 帧的抽样 QA，不应作为当前训练集。`z01_data.py qa` 保留为快速诊断入口，不能替代逐帧筛选。

## 训练与接触限制

关节速度惩罚同时作用于想象奖励和回放回报目标，在声明速度 90% 以上产生二次代价；评估使用原始跟踪奖励。它不会硬限制仿真关节速度，必须检查训练日志和策略实际轨迹。

轨迹筛选不保证动力学可行、足部无滑动、力矩/加速度合格，或与人类/G1 手臂姿态完全一致。参考播放器直接写入姿态，也不会通过物理响应消除穿地。

当前 5 ms 步长和默认 `solref="0.02 1"` 使用软接触。既有三个动作的 20 秒策略检查中，碰撞足底穿透中位数约 2–3 mm，瞬时最大约 24–29 mm，可见网格最大约 22–24 mm；发现接触不等于足底不会进入平面。选择训练设置时，应分别评估参考动作的地面对齐和仿真接触行为。

已有验证记录包括轨迹约束/相位对称测试、速度惩罚梯度测试、50 Hz 原样加载测试、5 秒 CPU 站立、200 次迭代的 GPU 短训练、20 次迭代的完整动作库检查及参考视频导出。历史短训练权重只验证流程；其中仍出现关节超速。保留的 `logs/z01_*` 是实验记录，最终权重应单独评估。

当前没有 Z01 的外部 sim2real 评测器或实机控制器集成。保留的单动作 ONNX 工具用于导出和仿真对照，不能据此认定可直接上机。
